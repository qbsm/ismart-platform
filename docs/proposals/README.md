# Proposals

Папка для **предложений по платформе** — паттернов, изменений архитектуры и фич, которые имеет смысл закрепить в baseline `ismart-platform` и распространить на deployment'ы (`kumho-tires.ru`, `italycommunity.ru`, `beepitron` и др.).

## Чем отличается от `docs/architecture/decisions/`

- **ADR** (`decisions/`) — решение **уже принято и реализовано** в baseline. Назначение: фиксация контекста, мотивации и последствий, чтобы потом не переоткрывать вопрос.
- **Proposal** (`proposals/`) — паттерн **обкатан на одном deployment'е**, но ещё не интегрирован в baseline. Назначение: задокументировать готовую реализацию, дать рецепт переноса, дождаться review и согласования. После принятия — мигрировать в `decisions/` как ADR.

## Структура файла

```
NNNN-короткий-slug.md
```

Содержит:
- **Контекст** — какая боль решается
- **Решение** — что именно предлагается (с file:line ссылками на reference implementation)
- **Структура файлов** — что добавить/изменить в `src/`, `config/`, `.env`
- **Миграция** — как существующий код переходит на новый паттерн
- **Пример расширения** — что делает разработчик, когда возникает новый случай
- **Reference implementation** — ссылка на deployment + коммиты, где паттерн уже работает
- **Acceptance** — критерии готовности к merge в baseline

## Жизненный цикл

```
Proposal (готов и обкатан) → review → принят → ADR (decisions/) + код в baseline → дистилляция в deployment'ы
                                  → отклонён → удалён / архивирован
```
