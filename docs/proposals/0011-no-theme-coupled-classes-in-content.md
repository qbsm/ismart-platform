# 0011 — Контент не несёт тему-зависимые presentational-классы (никаких scoped-оверрайдов под поверхность)

**Status**: Proposed
**Date**: 2026-05-29
**Author**: mgcom-avilon-tank deployment
**Scope**: core/convention — `data/json/global.json` (и любой контент с inline-классами), `assets/css/sections/*` (компоненты-поверхности)
**Related**: CLAUDE.md «Inline `<style>` в JSON-контенте запрещён», ADR-0009 (assets deployment-local)

---

## Контекст

В `global.json` контент несёт presentational-классы прямо в разметке/конфиге:

```json
"desc": "Мы используем <a href='/cookies-policy/' class='link color-2 weight-400'>cookie-файлы</a> ...",
"button": { "class": "button button-sm outline-color-2 button-animated animation-shift uppercase ..." }
```

`color-2` / `outline-color-2` — это **тёмный** цвет (`--color-2: #131616`). Класс выбран под светлую поверхность (исходно cookie-панель была белой, `background: var(--color-1)`).

Когда панель перевели в тёмное «стекло» (`--glass-bg`), тёмные текст/бордер стали **невидимы**. Чтобы починить, в `cookie-panel.css` появились scoped-оверрайды:

```css
.cookie-panel .desc .link.color-2 { color: var(--color-3); }
.cookie-panel .button-wrap .button.outline-color-2 { color: var(--color-1); border-color: var(--color-1); }
```

## Проблема

1. **Контент жёстко связан с темой поверхности.** Класс `color-2` корректен только на светлом фоне. Сменили фон секции → контент «сломался», хотя данные не менялись.
2. **Каскад scoped-оверрайдов.** Каждая поверхность, куда попадает такой контент, вынуждена переопределять `.surface .el.colorX { ... }`. Это:
   - дублирует логику цвета в нескольких местах,
   - хрупко (специфичность, порядок),
   - противоречит духу правила «не держать стиль в данных» (CLAUDE.md): класс `color-2` в данных — это тот же presentational-leak, что и inline `<style>`.
3. **Избыточность вскрывается не сразу.** Часть оверрайдов вообще не нужна: `.button { color: inherit }` + `body { color: var(--color-1) }` → кнопка и так наследует белый. Оверрайд `color: var(--color-1)` был no-op, но маскировал суть.

## Решение

**Контент не задаёт цвет под конкретную поверхность.** Цветом владеет компонент-поверхность (CSS), а данные используют либо семантически-нейтральные, либо бренд-акцентные классы, одинаково валидные на любой теме.

Конкретно для cookie-панели (применено в tank-avilon, 2026-05-29):

- ссылка в данных: `color-2` → `color-3` (бренд-акцент `--color-3`, виден и на светлом, и на тёмном);
- кнопка в данных: `outline-color-2` → `outline-color-3` (оранжевый бордер из стандартной утилиты);
- из `cookie-panel.css` **удалены оба** scoped-оверрайда — кнопка/ссылка снова стандартные.

Принципы:

1. **Бренд-акцент (`color-3`) тема-агностичен** — предпочтителен для ссылок/кнопок в контенте вместо `color-1`/`color-2`.
2. **Текст наследуется** — не дублировать `color: var(--color-1)` там, где `body`/поверхность уже задают цвет (`.button`/`.link` = `color: inherit`).
3. **Поверхность задаёт свой текстовый цвет один раз** (`.cookie-panel .desc { color: var(--color-1) }`), а вложенные интерактивные элементы наследуют — без per-element оверрайдов.
4. **Запрет на `.surface .el.colorX { color: ... }`** как способ «починить» контент: это сигнал, что класс в данных выбран неверно — править данные, а не плодить оверрайд.

## Миграция

1. Грепнуть контент на тему-зависимые классы: `grep -rn "color-2\|outline-color-2\|color-1" data/json/**/*.json`.
2. Для элементов на тёмных поверхностях заменить на `color-3` (акцент) или убрать класс (наследование).
3. Удалить соответствующие scoped-оверрайды в `assets/css/sections/*` / `components/*`.
4. Визуально проверить элемент на его поверхности (скриншот).

## Acceptance

- [ ] В `data/json` нет presentational-классов, завязанных на светлую тему, для контента, который рендерится на тёмных поверхностях
- [ ] `cookie-panel.css` не содержит `.cookie-panel ... .colorX`/`.outline-colorX` оверрайдов (применено в tank-avilon)
- [ ] Конвенция добавлена рядом с правилом про inline `<style>` (CLAUDE.md / `docs/conventions/`)
- [ ] При переносе в baseline — проверить kumho/italy/beepitron cookie-панель и прочие контент-ссылки/кнопки

## Открытые вопросы

1. Нужен ли в `helpers.css` явный тема-агностичный алиас (напр. `.color-accent` = `--color-3`), чтобы в данных не светились «номерные» цвета?
2. Стоит ли вынести cookie-панель `button.class`/`desc` из `global.json` в шаблон (данные → только текст ссылки/URL), убрав presentational-классы из данных полностью?
