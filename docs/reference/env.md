# Переменные окружения

Все параметры deployment'а задаются в `.env` в корне проекта (вне git, права 600).
Значения читаются в `config/settings.php`.

## Правило именования

**Префикс = имя канала или подсистемы, дальше параметр.** У каждого канала есть
`<КАНАЛ>_ENABLE` и `<КАНАЛ>_TIMEOUT`, остальное — специфика.

| Подсистема | Префикс |
| --- | --- |
| приложение | `APP_` |
| почта | `MAIL_` |
| CallTouch | `CALLTOUCH_` |
| Telegram | `TELEGRAM_` |
| Google Sheets | `SHEETS_` |
| резервный сбор заявок | `RESCUE_` |

Исторически имена разошлись на пять схем (`CT_`, `TG_`, `GS_`, `MAILER_`, `LEADS_API_`).
Читаются оба варианта: `App\Support\Env` берёт каноническое имя, а если его нет — прежнее.
Поэтому `.env` можно приводить в порядок постепенно; **в новых деплойментах используем
только канонические**.

## Приложение

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_ENV` | `development` | `production` включает кэш Twig и поднимает уровень логов |
| `APP_DEBUG` | `1` в dev, `0` в prod | Подробные ошибки |
| `APP_BASE_URL` | из текущего запроса | Абсолютные ссылки. **При Valet обязан совпадать с доменом стенда**, иначе лого и картинки уедут на чужой хост |
| `APP_DEFAULT_LANG` | первый из `global.json` | Язык по умолчанию |
| `YANDEX_METRIC_ID` | `0` | Счётчик Метрики; `0` — не подключать |

## Почта

| Переменная | Прежнее имя | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `MAIL_DSN` | `MAILER_DSN` | `sendmail://default` | Транспорт Symfony Mailer |
| `MAIL_TO` | — | пусто | Получатели через запятую. Пусто — канал выключен |
| `MAIL_FROM` | — | `noreply@localhost` | Отправитель |
| `MAIL_FROM_NAME` | — | пусто | Имя отправителя |
| `MAIL_SUBJECT_PREFIX` | — | пусто | Префикс темы |

Грабли: на sel почта идёт через `smtp://sel.ismart.pro:25` — **именно по этому имени**.
Сертификат mailcow покрывает `sel`, `mail`, `webmail`, `autoconfig`, `autodiscover`, но не
`localhost`: при `smtp://localhost:25` STARTTLS падает на несовпадении имени. Адрес
отправителя должен быть на нашем домене — `example.com` MTA отвергает (`nullMX`).

## CallTouch

| Переменная | Прежнее имя | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `CALLTOUCH_ENABLE` | `CT_ENABLE` | `false` | Включает канал заявок |
| `CALLTOUCH_ROUTE_KEY` | `CT_ROUTE_KEY` | пусто | Ключ автопрозвона форм. Вместе с токеном включает режим обратного звонка |
| `CALLTOUCH_TOKEN` | `CT_TOKEN` | пусто | Access-Token кабинета |
| `CALLTOUCH_SITE_ID` | `CT_SITE_ID` | пусто | Числовой ID кабинета. Включает режим регистрации заявки — **без токена и route key** |
| `CALLTOUCH_TIMEOUT` | `CT_TIMEOUT` | `10` | Таймаут запроса, секунды |
| `CALLTOUCH_CLIENT_ID` | — | пусто | Код счётчика подмены номеров (можно несколько через запятую) |
| `CALLTOUCH_CALLBACK_WIDGET_ID` | — | пусто | Ключ виджета обратного звонка для кнопок сайта |
| `CT_ROUTES` | — | пусто | Карта `route_key:token,route_key:token` для роутинга по ДЦ |

Режим выбирается по полноте набора: есть `ROUTE_KEY` и `TOKEN` — автопрозвон, иначе есть
`SITE_ID` — регистрация заявки. Автопрозвон приоритетнее: он ещё и звонит.

## Резервный сбор заявок

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RESCUE_ENABLE` | `false` | Включает дублирование заявки в наш сервис |
| `RESCUE_URL` | `https://api.ismart.pro/v1/rescue` | Адрес сервиса |
| `RESCUE_SITE` | пусто | Домен сайта, которым он представляется |
| `RESCUE_KEY` | пусто | Нужен только вне нашего периметра, см. ниже |
| `RESCUE_TIMEOUT` | `10` | Таймаут, секунды |

Смысл канала — «спасать» заявку от потери: сервис сначала её сохраняет, а потом раздаёт по
каналам с повторами, поэтому упавший канал не теряет лид (как случилось на чангане, где
одновременный отказ почты и CallTouch стоил 30 заявок).

Подтверждение отправителя идёт **по домену**: заявку шлёт бэкенд сайта, а значит с адреса,
на который домен и резолвится — чтобы прикинуться чужим доменом, надо оказаться на его
сервере. **Секрета в `.env` при этом нет** — только флаг, URL и собственный домен. Ключ
нужен лишь там, где DNS не различает: хостинг за CDN или на общем адресе. Соль для ключей
живёт на стороне сервиса, не в `.env` сайта.

Канал **добавочный**: `mail`, `telegram`, `google_sheets` остаются в ядре и включаются
своими флагами. Где политика заказчика запрещает отдавать данные в сторонний сервис —
просто не включаем `RESCUE_ENABLE`.

## Проверка

```bash
npm run channels:check     # что включено, что нет и чего не хватает
```

Показывает по каждому каналу состояние и причину, если он выключен. Секреты маскируются.

## Частые ошибки

- **Заявка «отправлена», но не дошла.** Форма отвечает успехом, если хоть что-то приняло
  заявку. Реальную картину даёт `channels` в ответе `/api/send` и запись «Канал не доставил»
  в `logs/app-*.log`. Мониторинг доставки живёт в `ismart-status-bot`.
- **Шаблонные адреса.** `noreply@example.com` из `.env.example` MTA отвергает — писем не
  будет вовсе.
- **`CALLTOUCH_ROUTE_KEY` заполнен, а заявки не идут.** Если в кабинете нет активного виджета
  с таким ключом, CallTouch отвечает 400 «нет активных виджетов». Конфигурация при этом
  выглядит здоровой.
