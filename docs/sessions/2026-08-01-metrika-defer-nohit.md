# 2026-08-01 — Метрика показывала 0 визитов: `defer: true` без вызова `hit`

## Проблема

На `kumho-tires.ru` счётчик Яндекс.Метрики 107236894 показывал 0 посещений. Проверка Метрики «Счетчик найден на странице» проходила успешно — тег на месте, но данных нет.

## Причина

В `templates/components/analytics.twig` в параметрах инициализации стоял `defer: true`:

```js
m[i](107236894, 'init', { defer: true, webvisor: true, ... });
```

`defer` в Метрике — это **запрет автоматической отправки просмотра страницы**; при нём данные уходят только после явного `ym(id, 'hit', url)`. Такого вызова в проекте нет (единственный вызов `ym` кроме init — `params` в `assets/js/utils/web-vitals.js`).

Появился в `125e3db` (23.03.2026), где заменил `ssr: true`. С этого момента визиты не считались.

### Как доказано

Сравнение сетевых логов headless-браузера (`--log-net-log`):

| Сайт | Запросы к `mc.yandex.ru/watch/<id>` |
|---|---|
| kumho-tires.ru (было) | все с `nohit=1`, `browser-info=pv:1` помечен как не-хит |
| doublestar.ru (счётчик работает, `defer` нет) | те же запросы **без** `nohit` |
| kumho-tires.ru (стало) | 4 запроса, `nohit` — 0 |

`nohit=1` — прямой маркер того, что тег просит Метрику не засчитывать просмотр.

## Что сделано

- **baseline** (`e1f5d5a`): убран `defer: true`; счётчик и noscript-пиксель больше не рендерятся без `YANDEX_METRIC_ID` — раньше подставлялся хардкод-фоллбэк `107236894` (счётчик kumho), из-за чего чужой ID уезжал в другие deployment'ы.
- **kumho-tires.ru** (`cebbcd2`): убран `defer`, выкачено на прод по FTP, проверено браузером — хиты уходят без `nohit`.
- **beepitron.com** (`c4de5cf`): убран `defer` + прописан собственный счётчик `18114082` (найден в домиграционном `beepitron.com-old/templates/layout.php`; в `.env` ID никогда не был задан → рендерился фоллбэк kumho). `.env` прода на Sprinthost обновлён по FTP, стейдж проверен. **Выкладка прода не завершена.**

## Аудит всех 95 доменов

Проверялись живые страницы: наличие тега, ID, `defer`, вызов `hit`.

- `businesscar-orel.ru` — на момент проверки домен не отвечал: сайт ещё не был выложен.

### Методика проверки

Текстовый grep по HTML недостаточен: на SPA/Vue счётчик лежит в JS-бандле, а на сайтах с GTM подгружается контейнером. Единственный надёжный способ — прогон в браузере с `--log-net-log` и поиск запросов к `mc.yandex.ru/watch/`. Параллельный запуск с `pkill` обрезает netlog и даёт ложные «хитов нет» — браузер должен завершиться сам (`--virtual-time-budget`), только потом читать лог. Контрольный сайт с заведомо рабочим счётчиком в выборке обязателен.
