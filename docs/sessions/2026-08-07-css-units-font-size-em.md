# 2026-08-07 — Чистка font-size: em (css-naming §4) + якоря шкалы в чекере

## Контекст

Возврат к бэклогу из сессии [2026-06-01](2026-06-01-css-units-and-form-callback-normalization.md):
«чистка css-units нарушений (baseline 133) с рендер-проверкой». В этот заход закрыта
текстовая половина правила — `font-size` → `em`. Layout-половина (`px` → `rem`) не трогалась.

Прогон `npm run check:css-units`: было **133** нарушения в 17 файлах, стало **97** в 14.
Текстовых (`[текст]`) — **0**.

## 1. font-size в px → em

Три секции (`hero`, `partners`, `trust`) — чужой код с `px`-типографикой; плюс `critical.css`.

| Файл | Было | Стало |
| --- | --- | --- |
| `sections/hero.css` | 11× px: 28/36/44, 17, 20, 14×2, 13×2, 15, 12 | `2em`, `2.6em`, `2.75em`, `1.2em`, `1.4em`, `1em`, `0.95em`, `1.1em`, `0.85em` |
| `sections/partners.css` | 7× px: 12×2, 32, 16, 15, 28, 14 | `0.85em`, `2.3em`, `1.15em`, `1.1em`, `2em`, `1em` |
| `sections/trust.css` | 3× px: 22, 15, 13 | `1.6em`, `1.1em`, `0.95em` |
| `sections/cookie-panel.css` | `.desc { 1.4rem }` | `1em` |
| `critical.css` | `body { font-size: 16px }` | `html { font-size: 10px }` + `body { 1.4rem }` + `@media (min-width: 1200px) { body { 1.6rem } }` |

Значения em выбраны по сетке 0.05 от базы 14 px (мобильная база `body`), как в
`base/typography.css`. Отклонение от исходных px — не более 0.4 px.

Побочно: `critical.css` инлайнится в `<head>` и задавал `body` 16 px, тогда как
`main.css` задаёт 14 px до 1200 px. На мобильных текст прыгал 16 → 14 px в момент
загрузки основного бандла. Теперь оба файла объявляют базу одинаково.
`line-height` остаётся рассинхронизированным (`1.5` в critical против `1.2` в
typography) — не правил, отдельный вопрос.

## 2. Якоря шкалы: `rem` для font-size узаконен

Оставшиеся 13 текстовых нарушений были `rem` в местах, где `rem` осознан.
Решение пользователя: **`body` оставить как есть — это база.**

Зафиксировано в `docs/conventions/css-naming.md` §4 как явное исключение:

- `html` (`font-size: 10px`) и `body` + поля ввода (`input`, `select`, `textarea`) —
  задают саму шкалу, от них считается весь `em` ниже по дереву;
- `.button` и размерные модификаторы — font-size стоит рядом с `height`/`padding` в
  `rem`; `em` расцепил бы текст с коробкой (на ≥1200 px шрифт вырос бы в неизменных 5.6rem);
- `form-callback` — компонент со своей `rem`-шкалой токенов (`--fc-font-size*`),
  смешивать её с `em` внутри одного компонента нельзя.

## 3. `check-css-units.js`

- Добавлен `TEXT_REM_ANCHORS` — список селекторов-якорей (дублирует конвенцию, ссылка
  проставлена в обе стороны). Срабатывает только на `rem` и только если **все**
  части составного селектора — якоря (`.button, .card { 1.5rem }` остаётся нарушением).
- Починен разбор вложенных `@media`: селектор берётся ближайшим `rule` вверх по дереву
  (`nearestSelector`), раньше `decl.parent.selector` у вложенной декларации был `undefined`,
  и `body { @media (--lg) { font-size: 1.6rem } }` не сопоставлялся с селектором.

## Verify

- `npm run build:critical`, `npm run build:css` — успешно; `critical.min.css` содержит
  `html{font-size:10px}` и медиа-блок.
- `npm run lint:css` — 0 ошибок; `vitest` — 21/21.
- `check:css-units` — текстовых нарушений 0; негативный тест на синтетическом CSS
  подтвердил, что `.card { 1.4rem }`, `.card__title { 14px }`, смешанный
  `.button, .card` и `.buttonish` по-прежнему ловятся.
- **Рендер-проверка:** секции `hero/partners/trust` не подключены ни к одной странице
  baseline (`data/json/ru/pages/index.json` — только `intro`), поэтому размеры сверялись
  на временном стенде с собранным бандлом через `php -S` + headless Chrome, на 375/800/1440 px.
  Вычисленные `font-size` на 375/800 совпали с прежними px (±0.4 px), на 1440 текст
  масштабируется от базы 16 px — целевое поведение правила. Стенд удалён.
