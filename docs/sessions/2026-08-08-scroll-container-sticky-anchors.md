# 2026-08-08 — Скролл-контейнер: документ вместо body, sticky и якоря

## Контекст

На `italycommunity.ru/events/uzhin-v-osobnyake` якорь `#buy` вёл себя неправильно.
Задача: проверить гипотезу и перенести фикс, сделанный ранее в deployment'е
`businesscar-orel.ru` (коммиты `54faf44` — CSS, `5685e99` — бургер).

Происхождение проблемы (со слов пользователя): стили пришли по наследству от
`lburo.ru`, где не работал sticky-блок с владельцами на главной.

## Механика

`overflow-x: hidden` на `html`/`body` сам по себе делает элемент скролл-контейнером
по другой оси — из-за этого и ломался `position: sticky`. Вместо снятия первопричины
добавили `body { height: 100% }`: body стал полноценным скролл-контейнером, sticky
ожил, но документ скроллиться перестал. Последствия на проде italycommunity:

- `documentElement.scrollHeight == clientHeight == 844` — документ не скроллится;
- `window.scrollTo()` — no-op, `window.pageYOffset` всегда 0;
- `scroll-padding-top` на `html` игнорируется (у скроллера — body);
- на iOS после якорного перехода прокрутка «залипает».

`overflow-x: clip` снимает первопричину: он не создаёт скролл-контейнер, поэтому
sticky работает и без `height: 100%`.

Проверка гипотезы на живом `lburo.ru` (источник наследства): sticky-блок владельцев
`.studio .section__item.owners-wrap` держится на `top: 70px` и до, и после патча
(`clip` + снятый `height: 100%`) — то есть обход больше не нужен.

## Патч ядра (этот репозиторий)

Baseline нёс ровно тот же унаследованный паттерн, имея при этом два sticky-блока
(`sections/header.css:12`, `pages/tires.css:197`) и ни одного `scroll-padding`.

- `assets/css/base/general.css` — у `body` снят `height: 100%`; `overflow-x: hidden`
  → `clip` на `html, body`; на `html` добавлен
  `scroll-padding-top: calc(var(--header-top-offset) + var(--header-fixed-height) + 1rem)`.
  Переменные уже существовали в `sections/header.css` (`:root`), заводить не пришлось.
- `assets/js/components/burger-icon.js` — блокировка фона переведена на `overflow`
  у `html`; обработчик «клик вне меню» теперь выходит сразу, если меню закрыто.
  **Парность обязательна:** прежний обработчик висел на документе, срабатывал
  независимо от состояния меню и делал `window.scrollTo(0, scrollPosition)` с
  дефолтным `0`. Пока `scrollTo` был мёртв, это не проявлялось — после CSS-фикса
  любой клик по странице уносил бы её в начало.

### Verify

- `build:css` / `build:js` — успешно; `lint:css` — 0 ошибок; `vitest` — 21/21.
- Рантайм (`php -S` + headless Chrome): `overflow-x: clip/clip`,
  `scroll-padding-top` = 67px (0.5+5.2+1 rem) и 102px при `--lg` (2+7.2+1 rem) —
  считается из существующих переменных. На низком вьюпорте (390×300):
  `docScrolls: true`, `window.scrollTo(0,200)` → `pageYOffset: 200`,
  `body.scrollTop: 0` — скроллит документ.
- **Ограничение:** дефолтный dataset baseline (`index.json` — только `intro`) короче
  вьюпорта и не содержит `.header`, поэтому липкая шапка и якорные переходы
  проверены на deployment'е, не здесь. Локальный прогон baseline требует
  `APP_BASE_URL` под текущий хост — в `.env` стоит `https://example.test/`,
  из-за чего CSS уходит на несуществующий хост (поднимал через
  `APP_BASE_URL=http://127.0.0.1:8405/ php -S`).

### Оговорка по совместимости

`overflow-x: clip` не поддерживается в Safari ≤15 (там правило игнорируется и
горизонтальный оверфлоу снова становится видимым). Тот же размен уже принят в
`businesscar-orel.ru`.

## Что осталось в deployment'ах, а не в baseline

- **`AssetExtension::getInlineCss`** — в italycommunity инлайнится весь main.css и
  относительные `url(../../…)` переписываются в абсолютные; замена ловила только
  форму без кавычек, поэтому в dev-сборке (кавычки не срезаны) шрифты уходили в
  `/fonts/…` → 404. Починено там переводом на `preg_replace_callback`. В baseline
  инлайнится только critical.css без `url()`, метод ничего не переписывает —
  портировать нечего, но расхождение стоит держать в виду.
- **`DataExtension::getImageDimensions`** — baseline **впереди**: `normalizeManifestKey()`
  уже принимает абсолютные URL. В italycommunity была старая узкая версия
  (`preg_replace('#^data/img/#')`), из-за чего размеры не находились для `covers`,
  которые нормализуются в absolute до рендера. Deployment подтянут точечно;
  полноценный sync `DataExtension` (вместе с `imageHas`/raw-source) — отдельной задачей.
- **Индексация «готовых» webp** — baseline уже покрывает webp-исходники конвенцией
  `**/raw/*.webp` (ADR-0007). У italycommunity картинки событий лежат плоско
  (`events/<slug>/hero.webp`), под это в deployment добавлен `--index-only`.
  В baseline не переносим: правильный путь — миграция картинок на `raw/`-раскладку.

## Раскатка по парку (тот же день)

Состав взят по маркеру `src/Action/PageAction.php` — инвентарь `docs/inventory/deployments.md`
устарел (в нём нет avilon-семейства). Источник правды — прод-каталоги на sel, не локальные
снапшоты: 7 из 9 локальных репозиториев avilon отставали или разошлись с продом.

**Ловушка git на проде.** У `root` нет ключей к этим репозиториям (deploy key только на
sollers), поэтому `git fetch` в прод-каталогах молча не обновляет ссылки. Прод живёт со
стухшими `origin/*`, и сверка «прод против origin» изнутри прода врёт: на havalavilon прод
считал `origin/main = f9d9b2f`, реальный origin — `58561a5`, сам прод — `de43ddb`.
Достоверный источник — `sudo -u promo git ls-remote`.

**Сведение расхождений (4 репо).** Коммиты с одинаковыми заголовками существовали с обеих
сторон разными хешами — одна работа, закоммиченная дважды (руками на проде и через git);
`git patch-id --stable` совпал побайтово. Реально уникальны были по одному коммиту с каждой
стороны, и файлы не пересекались: в origin — «Сборка изображений» (build-тулинг), на проде —
`fix(preview): session_start без cache_limiter`. Схема: база = прод, cherry-pick тулинга
сверху, затем фикс, затем перезапись ветки. Ничего не потеряно.

**Применено** в 15 репозиториях: `body` без `height: 100%`, `overflow-x → clip`,
`scroll-padding-top` там, где есть переменные шапки (kumho, auchan), фикс `getInlineCss`
(avilon-семейство) и бургер. Бургер перезаписывался только при байт-в-байт совпадении с
эталоном (14 из 15); beepitron разошёлся, но его обработчик уже защищён состоянием меню —
оставлен как есть.

**Выкачено:** 9 прод-каталогов avilon + 9 стейджей + стейдж kumho. Проверено на живых
сайтах: `overflow-x: clip`, `docScrolls: true`, `window.scrollTo` работает, шапка липкая,
бургер не сбрасывает позицию, якорь `#map` встаёт ровно на `scroll-padding` (67px при шапке
52). **Важное:** `scroll-padding-top` на всех avilon-сайтах был прописан давно, но был
мёртвым кодом — скроллил `body`, и padding на `html` игнорировался.

**Не закрыто:** beepitron (origin разошёлся на 131↔129 коммитов — форсить не стали),
doublestar (remote не настроен), auchan-стейдж стоит на ветке `master`, а коммит ушёл в
`feat/staging-noindex`; kumho/trazano/mirage — FTP, отдельный метод.

## Побочная находка: бандл старше исходника

На havalpro бандл был собран 04.08 в 17:49, а коммит с фиксом — в 18:48. Код в git был
правильный, а сайт месяц отдавал старую логику. Отсюда правило для чек-листа деплоя:
после `pull` сборка обязательна, и стоит сверять, что бандл не старше последнего коммита
по `assets/**`. Раскатка это чинит попутно, так как пересобирает каждый сайт.

## Кандидаты на ADR

1. **Скролл-контейнер — всегда документ.** Запрет `body { height: 100% }` и
   `overflow-x: hidden` на `html`/`body`; отступ под липкую шапку — только глобальный
   `scroll-padding-top` на `html`, точечные `scroll-margin-top` по секциям запрещены.
2. **Сборка — часть выкладки.** См. находку выше.
3. **Готовность стороннего SDK — по его колбэку, не по геометрии DOM.** См.
   `docs.ismart.pro/promo.havalpro-avilon.ru` — гейт `iframe.width > 0` описывал только
   десктопный вид виджета CallTouch и полностью ломал мобильный.
4. **Якоря шкалы для font-size** — уже в `css-naming.md §4`, можно поднять до ADR.

## Дальше

- em/rem по парку отдельным заходом: сперва раскатать конвенцию + `check-css-units.js`
  с `TEXT_REM_ANCHORS`, чтобы получить честные списки, затем править по репо с визуальной
  проверкой. Массовая автозамена `px → em` невозможна — нужен родительский контекст.
- Точечные `scroll-margin-top` в deployment'ах снимать при раскатке: с глобальным
  `scroll-padding-top` они складываются и уводят якорь вдвое (в italycommunity
  `.event-buy { scroll-margin-top: 13rem }` давал ровно +130px).
