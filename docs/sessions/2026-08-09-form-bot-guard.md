# 2026-08-09 — Защита форм от роботов: токен по запросу, возраст отправки, ловушка

На kumho через форму контактов прошла спам-заявка: имя «Александр / kumho-tires.ru», номер
`79990000000`, текст с рекламой SEO-услуг. В User-Agent — `HeadlessChrome/145`.

## Почему прежние проверки не сработали

CSRF-токен проверялся строго (`hash_equals` с сессионным), но робот получал его честно: он
открывает страницу браузером и забирает токен вместе с HTML. Ловушки в платформе не было
вовсе — `validate()` смотрел только длину телефона, согласие и формат email. Rate limit
(10 запросов в минуту) одна заявка в сутки не трогает.

## Что сделано

**Токен формы выдаётся по запросу.** `GET /api/form-token` отдаёт `время.подпись`; в HTML
токена нет, JS запрашивает его при первом касании поля (`primeFormToken`). Страница, скачанная
роботом, отправить заявку не даёт.

**Возраст отправки.** Между выдачей токена и заявкой должно пройти не меньше трёх секунд —
мгновенная отправка не человеческая. Причём скорость перебивает и сессионный токен: он не
спасает заявку, помеченную `too_fast`.

**Ловушка.** Скрытое поле `company_site` за пределами экрана. Заполнено — отвечаем как при
успехе и никуда не шлём, иначе робот подберёт набор полей и вернётся.

**Токен не зависит от сессии.** Подпись HMAC по времени выдачи, секрет заводится сам в
`cache/form-token-secret`. Потерянная сессионная кука (приватный режим, ITP, блокировщики)
больше не означает отказ на уже заполненной форме.

## Чтобы не потерять ни одной заявки

Сервер принимает **оба** токена: новый и сессионный. Пока новый JS расходится по парку, а
у кого-то открыта страница, отрендеренная до выкладки, заявка уходит по старому пути. Отказ —
только когда не подошёл ни один токен, и тогда причина пишется в лог.

Проверено на живом стенде:

```
мгновенная отправка               419    ловушка заполнена     200, каналов ноль
через 4 секунды                   200    только старый токен   200
без токенов вовсе (curl-бот)      419    подделка подписи      419
```

## Раскатка

Файлы deployment'ов давно разошлись с ядром, поэтому перенос точечный и идемпотентный
(`apply-form-guard.py`). Приведены к одному состоянию 13 боевых доменов: девять промо Авилона,
italycommunity, kumho (FTP), beepitron (FTP), businesscar (SFTP) — плюс их стейджи. Везде
`/api/form-token` отдаёт токен, главная 200.

Не попал `auchan-promo.svr-avto.ru`: прод на отдельном аккаунте reg.ru, FTP-креды не сохранены
(о чём прямо сказано в его PROJECT.md).

## Побочно

- `/_f` принимал только GET, а `sendBeacon` шлёт POST — на площадках с чужим nginx события
  воронки терялись. Теперь маршрут принимает оба метода.
- Класса `App\Support\Env` на deployment'ах нет: секрет читается через `getenv`.
- У `italycommunity` маршрут `/api/send` объявлен без `[/]`, поэтому общий патч не лёг —
  маршрут добавлен отдельно.
