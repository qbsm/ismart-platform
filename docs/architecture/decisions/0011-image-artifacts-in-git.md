# ADR-0011: Артефакты изображений в git, `build:images` — инкрементальный инструмент разработчика

**Status**: Accepted
**Date**: 2026-08-03
**Дополняет**: [ADR-0006](0006-manifest-driven-images.md), [ADR-0007](0007-raw-source-picture.md)

## Context

Платформа хранила **size-варианты** (`data/img/**/{400…2560}/*.{webp,avif}`) в git, а **манифест**
`assets/img/build/image-dimensions.json` — в `.gitignore`. Комбинация оказалась худшей из возможных:
без манифеста `picture()` отдаёт пустой `<img>` (ADR-0006, п. graceful fallback работает только
на свежем клоне — при наличии старого манифеста новые картинки просто выпадают), а получить манифест
можно было единственным способом — полной пересборкой всех изображений на сервере.

`tools/build/build-images.js` при этом не имел инкрементальности: `processImage()` безусловно
перекодировал каждый вариант при каждом запуске. Следствия, зафиксированные на живом деплое
2026-08-03 (`promo.moskvich-avilon.ru`):

- полный прогон — 59 исходников → 630 выходных файлов, ~13–15 минут на sel-сервере;
- sharp/libvips на сервере другой версии, чем у разработчика → после сборки ~277 «изменённых»
  картинок с идентичными пикселями и другими байтами → `git pull --ff-only` в прод-каталоге падает;
- деплой не атомарен: контент со ссылками на новые картинки приезжал `git pull`'ом раньше, чем
  досчитывался манифест → секция акций больше получаса стояла с пустыми обложками на проде.

## Decision

**Все артефакты изображений хранятся в git — и варианты, и манифест.** Сервер не собирает
изображения вообще; `build:images` — инструмент разработчика.

1. `assets/img/build/image-dimensions.json` снят с `.gitignore` (`!assets/img/build/image-dimensions.json`)
   и коммитится вместе с вариантами, которые он описывает.
2. Деплой = `git pull`. `build:images` из деплой-процедуры исключается (остаются `build:css`/`build:js`,
   их артефакты в git не хранятся).
3. `build-images.js` становится инкрементальным: вариант перекодируется, только если его нет,
   он старше исходника или не читается; иначе размеры для манифеста берутся из готового файла.
4. Добавлена селективность — фильтр по конкретной картинке/папке/glob, `--size=`, `--format=`, `--force`.
   Полный прогон дополняет манифест целиком (чистит устаревшие ключи), частичный — дополняет существующий.

Отвергнутая альтернатива — **артефакты вне git** (в репозитории только `raw/`, всё производное
собирается на деплое): даёт лёгкий репозиторий и исключает расхождение байтов, но требует sharp
на каждом сервере и неприменима к FTP-хостам (`DEPLOY.md`, метод 3), где сборки на хосте нет в принципе.
Медиа платформы и так лежат в git целиком, так что вариант «всё в git» согласован с существующим укладом.

## Consequences

### Положительные

- Класс инцидента «контент приехал, манифест — нет» закрыт: манифест едет тем же коммитом, что и картинки.
- `git pull --ff-only` в прод-каталогах больше не грязнится пересборкой — сервер ничего не пересобирает.
- Полный `build:images` у разработчика — секунды вместо минут (0 перекодирований, если ничего не менялось).
- Точечная пересборка: `node tools/build/build-images.js data/img/actions/raw/m3-road.webp`.
- Работает на FTP-хостах без изменений процедуры.

### Отрицательные

- Репозитории тяжелее: варианты и манифест — обязательная часть коммита. Для платформы, где `data/img`
  и так в git ([project_full_media_in_git]), это не новый класс расходов.
- Разработчик обязан запускать `build:images` перед коммитом новых картинок и коммитить манифест.
  Это ужесточение уже зафиксированного в ADR-0006 требования, а не новое.
- Инкрементальность опирается на mtime, а git его не сохраняет: на свежем клоне mtime всех файлов
  — время клонирования, поэтому варианты считаются актуальными. Для варианта B это корректно
  (в git лежат ровно те файлы, что нужны), но означает, что mtime-эвристика не годится как
  единственный сторож при переходе к сборке на сервере.

### Решения, оставленные на потом

- **Инкрементальность по хешу исходника + параметрам кодирования** вместо mtime: ключ
  `sha1(raw) + width + format + quality + effort` в `assets/img/build/image-build-cache.json`.
  Переживает клон, ловит смену `config/image-sizes.json` и quality.
- **Параллелизм** по числу ядер (`p-limit`) — сейчас кодирование строго последовательное.
- **`check-image-references.js`** (перенесено из ADR-0006) — линтер orphan-ссылок JSON → манифест;
  под вариантом B он же ловит «картинка добавлена, манифест не пересобран» до коммита.
